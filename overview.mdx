Hindsight is the **deal memory layer** for your GTM stack. It continuously turns the evidence scattered across calls, emails, CRM records, documents, and warehouse data into a verified, structured memory of each account and opportunity.

The result is more than a deal summary. Hindsight reconstructs what happened, why it happened, and how the team executed; preserves the supporting evidence; and makes relevant prior experience available when a new opportunity needs it. Your team and AI agents can query that memory directly through the [Model Context Protocol (MCP)](/integrations/mcp) or the [REST API](/integrations/api).

For **RevOps and enablement**, this creates a dependable operating record without relying on manual CRM hygiene. For **AI engineers**, it provides a cited, workspace-scoped tool surface—without building ingestion, retrieval, entity resolution, comparison, and verification infrastructure for every workflow.

## Why deal memory

Every opportunity generates experience, but most organizations cannot reuse it. The evidence is distributed, inconsistently labeled, and difficult for a person—or an agent—to evaluate in the context of the next deal.

<CardGroup cols={3}>
  <Card title="Fragmentation" icon="puzzle-piece">
    Deal context is split across call recordings, email threads, CRM fields, documents, and systems of record—without a canonical view of the opportunity.
  </Card>
  <Card title="Unreliability" icon="triangle-exclamation">
    CRM fields are incomplete, terms vary by team, and transcripts are noisy. Raw retrieval alone cannot establish what actually happened or which evidence supports a conclusion.
  </Card>
  <Card title="Experience does not compound" icon="coins">
    Prior wins and losses stay trapped in source systems. Teams repeatedly research the same objections, buyer requirements, and execution risks instead of applying proven experience.
  </Card>
</CardGroup>

## How Hindsight builds deal memory

At the core is the **Analyze Engine**. For each deal, it aggregates related calls, emails, CRM records, documents, and other available evidence. It reconciles that evidence into an account and deal record that captures the commercial context, outcome, and supporting sources.

The memory captures dimensions that make past experience comparable and reusable: buyer and stakeholder context, product signals, competitive position, decision drivers, commercial fit, and sales execution. As new evidence arrives and deals advance, Hindsight refreshes the record rather than leaving a point-in-time summary behind.

Every tool reads from this memory layer. Retrieval, reconciliation, and evidence linking happen server-side, so agents can work from clean, cited context instead of reprocessing raw transcripts on every call.

  <Card title="Verified, not inferred" icon="shield-check">

  </Card>

### Data sources

**Your CRM is the backbone — and the only required source.** Connect Salesforce or HubSpot and Hindsight pulls each opportunity and its associated objects, along with the related account and contact objects. You control exactly which properties come across from the **CRM settings page** in your dashboard. For many teams that's enough on its own—the CRM is already the centralizer, and Hindsight builds the verified deal memory from what is there.

**Context sources are optional enrichment.** When you want more than what lives on the CRM record — full call transcripts and the actual content behind a deal — connect dedicated sources and Hindsight ingests the full signal:

| Type | Sources |
|---|---|
| CRM (required) | Salesforce, HubSpot |
| Calls | Gong, Clari, Outreach Kaia, Fathom, Fireflies, Avoma |
| API | Upload any document or transcript directly — see [REST API uploads](/integrations/api) |

Hindsight is **format-flexible**: PDFs, Office files, Markdown, audio, and video are all ingested, and call recordings are transcribed automatically.

<Info>
  **Warehouse your data in Snowflake?** On the Enterprise plan, Hindsight can ingest directly via a Snowflake data share — no manual exports or uploads required.
</Info>

### Sync & analysis cadence

By default, Hindsight pulls the latest from connected integrations **every 12 hours** while a deal is open and continues for **14 days after it closes**. By default, deal analysis re-runs on **every stage change** and whenever **new context sources are uploaded**—so the deal memory stays current as the opportunity moves.

You control when deal analysis runs. **Enterprise customers can also configure custom integration sync schedules** to match their data-refresh and operating requirements.

## Query and apply the memory

Hindsight is API-first. Query account and deal memory through two integration surfaces, then use the resulting experience in your agents, applications, and operating workflows.

<CardGroup cols={2}>
  <Card title="MCP" icon="plug" href="/integrations/mcp">
    A composable tool surface your AI assistant orchestrates directly. Use it to inspect deal context, find comparable experience, retrieve evidence, and analyze pipeline data in Claude, ChatGPT, Cursor, Cline, or your own MCP client. **Start here for agent use cases.**
  </Card>
  <Card title="REST API" icon="code" href="/integrations/api">
    A single endpoint that runs Hindsight's agent server-side and returns a complete, cited answer. Best for Glean, Slack bots, embedded search, and workflows that want a finished response.
  </Card>
</CardGroup>

**Rule of thumb:** use **MCP** when *your* model should choose the tools and control the execution path. Use the **REST API** when you want Hindsight to orchestrate retrieval and synthesis, then return a cited answer.

Authentication is the same for both — a Bearer API key scoped to your workspace. Generate one from **Settings → API Keys** in the [Hindsight app](https://app.usehindsight.com/settings/keys).

## Tools available

The MCP server exposes the deal memory layer as a focused set of tools. They fall into seven groups. Most agent workflows start with **`fetch_hindsight_context`** to learn the workspace's competitors and deal stages, then branch into the relevant group.

### Context & schema

Orient the agent before it queries — what competitors and stages exist, and what fields the deal grid has.

| Tool | Description |
|---|---|
| `fetch_hindsight_context` | Fetch competitors and deal stages needed to use the other tools. Usually the first call. |
| `pull_schema` | Fetch the CRM field schema for your workspace — field names and types for the deal grid. |

### Deals & pipeline

Find, triage, and read individual deals and their underlying documents.

| Tool | Description |
|---|---|
| `select_deal` | Filter and list deals by criteria. Returns lean rows for fast triage. |
| `get_deal` | Get full details for specific deals by ID. |
| `search_comparable_deals` | Find the most comparable historical deals for a source deal, including each matching dimension and score. |
| `search_across_deals` | Search all deal documents across the entire pipeline. |
| `search_deal_documents` | Deep search within specific deals. |
| `pull_full_document` | Fetch full document content by ID when retrieved chunks aren't enough. |

### Competitive intelligence

Query your competitive content and saved intel.

| Tool | Description |
|---|---|
| `search_competitive_assets` | Search battlecards and competitive assets. |
| `search_competitive_intel` | Search pre-saved competitive intelligence. |

### Knowledge base

| Tool | Description |
|---|---|
| `search_knowledge_base` | Search your company's messaging docs, playbooks, and positioning. |

### Live web research

Reach beyond stored data for current market and competitor information.

| Tool | Description |
|---|---|
| `search_web` | Live web search for competitive and market research. |
| `scrape_url` | Extract content from a specific URL. |
| `map_site_urls` | Discover and map the structure of a website. |

### Quantitative analysis

Build and analyze structured datasets from the deal grid for win-rate, trend, and segment questions.

| Tool | Description |
|---|---|
| `create_dataset` | Build a structured dataset from your deal pipeline. |
| `run_sandbox_dataset_analysis` | Run custom Python analysis against an authorized dataset in Hindsight's isolated, network-disabled sandbox. Can return up to three charts. |

### Write back

| Tool | Description |
|---|---|
| `upload_deal_document` | Attach a document to a deal — pass the text directly or a downloadable file URL. |
| `upload_to_knowledge_base` | Upload your company's docs, playbooks, case studies, or approved messaging to the knowledge base. |
| `upload_competitive_intel` | Save competitor pricing, positioning, feature notes, or gathered news to the knowledge base. |

<Note>
Tool availability is role-based. By default, workspace admins can use every tool; managers can use the read tools plus the data-analysis tools; and members can use the read tools. Workspace admins can customize these permissions in **Settings → MCP Tools**.
</Note>

<Note>
  The canonical tool list is generated from the live MCP server. Names and parameters can change between releases — call `tools/list` against the [MCP endpoint](/integrations/mcp) for the exact current surface.
</Note>
